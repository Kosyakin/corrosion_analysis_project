# Рекомендации по стилю для LLM (русская научно‑техническая статья)

Цель: единый академический стиль при подготовке текста для журналов технического профиля (IMRAD), с учётом практик российских изданий и особенностей проекта (in‑DB подготовка данных в PostgreSQL).

## 1. Общие принципы
- Научно‑деловой стиль: без разговорных оборотов; использовать безличные и пассивные конструкции («показано», «предложена методика»).
- Последовательная терминология по всему тексту.
- При первом упоминании русское название + английский термин в скобках; далее использовать русское/аббревиатуру. Допустимые сокращения: ML, RBI, API 579, feature store (витрина признаков).
- Ссылки на литературу — квадратными скобками [n]; нумерация в порядке цитирования (если журнал не требует иного).
- Ссылки внутри текста: «см. рис. 1», «см. табл. 2», «формула (1)».

## 2. Структура (IMRAD)
1) Введение: актуальность, цель, новизна/вклад (0,5–1 стр.).  
2) Материалы и методы: данные, схема БД, алгоритмы (детекция замен, RBI, индексы), архитектура MVs.  
3) Результаты и обсуждение: для этой статьи — результат в виде воспроизводимого датасета/витрины признаков, стабильность и воспроизводимость (без сравнения ML‑моделей; метрики — в следующей статье).  
4) Заключение: выводы, ограничения, планы.  
Отдельно: Аннотация и ключевые слова (RU/EN), Список литературы по ГОСТ.

## 3. Обозначения, единицы, числа
- Единицы — СИ. Символы и сокращения расшифровывать при первом упоминании.
- Десятичный разделитель — по требованиям журнала (по умолчанию запятая 1,25); диапазоны «0,3–0,5».
- Химические формулы — с нижними индексами: H₂S, CO₂, Cl₂, HCl.
- Имёна объектов БД — без ковычек: measurements, components, mv_ml_pipeline_training_set.

## 4. Формулы
- Выделять в отдельные строки, нумерация сквозная или по разделам: (1).  
- Ссылки в тексте: «см. (1)».  
- Пример:  
  \( V_{\mathrm{corr}} = \dfrac{T_{n-1} - T_n}{\Delta t} \),  
  где \(T_{n-1}, T_n\) — толщины, \(\Delta t\) — интервал в годах.

## 5. Рисунки и таблицы
- Нумерация: Рисунок 1, Рисунок 2; Таблица 1, Таблица 2.  
- Подпись: снизу для рисунков, сверху для таблиц; кратко и по сути.  
- В тексте обязательно сослаться перед первым появлением.  
- Графика ≥300 dpi; не дублировать одни и те же данные в тексте/таблице/рисунке.

## 6. Список литературы
- ГОСТ Р 7.0.5‑2008 (ссылки) и ГОСТ 7.1‑2003 (описание); оформление источников по требованиям журнала.  
- Иностранные источники — оригинальные названия; при необходимости — транслитерация.

## 7. Язык и англицизмы
- Предпочтительно русские термины; англ. термин — только при первом упоминании в скобках.  
- Допускается использование общепринятых аббревиатур (ML, RBI).  
- Термины домена данных: «витрина признаков (feature store)», «in‑DB (на уровне СУБД)».

## 8. Специфика проекта (коррозия, in‑DB pipeline)
- Акценты: формальное определение целевой величины \(V_{\mathrm{corr}}\); правила детекции замен; RBI‑агрегация (worst‑case); индексы химической агрессивности; количественная стойкость материалов.  
- Для схем БД использовать ER‑диаграмму (Рисунок 1) и схему конвейера MVs (Рисунок 2).  
- В тексте указывать связки «таблица (…); см. рис. 1» без избыточных повторов.

## 9. Примеры фрагментов
- Ссылка на объект БД: «Данные неразрушающего контроля (`measurements`; см. рис. 1) …».
- Подпись к рисунку (лаконично):  
  «Рисунок 1 — ER‑диаграмма схемы `public`: основные сущности и связи».
- Подпись к таблице:  
  «Таблица 1 — Категории материалов и коэффициенты стойкости».

## 10. Аннотация и ключевые слова
- Аннотация 150–250 слов (RU/EN), без ссылок и формул; отражает цель, метод, новизну, результат (витрина признаков).  
- Ключевые слова ≤10: «коррозия», «витрина признаков», «RBI», «PostgreSQL», «скорость коррозии», «H₂S», «feature store», «in‑DB».

---
Применение: LLM должен придерживаться этих правил по умолчанию. Специфические требования журнала (шрифт, поля, стиль ссылок) — уточнять и приоритетно применять, не противореча разделам 1–10.*
*Не использовать очень длинное тире
