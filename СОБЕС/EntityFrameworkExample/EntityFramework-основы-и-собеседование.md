# Entity Framework Core — основы и что спросят на собеседовании

## Что такое Entity Framework (EF)?

**EF Core** — ORM (Object-Relational Mapper) от Microsoft для .NET: работа с БД через объекты и LINQ, без написания SQL (хотя SQL при необходимости доступен).

---

## Основные понятия

| Понятие | Кратко |
|--------|--------|
| **DbContext** | Сессия с БД: набор DbSet\<T\>, отслеживание изменений, SaveChanges, конфигурация. |
| **DbSet\<T\>** | Набор сущностей типа T (таблица/представление). |
| **Entity** | Класс, сопоставленный с таблицей. Обычно с первичным ключом (Id). |
| **Migration** | Версионирование схемы БД: код-описание изменений, применяется к БД командой. |

---

## Жизненный цикл и способы регистрации DbContext

- **AddDbContext\<T\>()** — по умолчанию **Scoped**: один экземпляр на один запрос (в ASP.NET). Не использовать один контекст в многопоточности.
- **AddDbContextPool\<T\>()** — пул контекстов, меньше накладных расходов при частом создании.
- Контекст **не thread-safe**: один контекст — один поток/запрос.

## Что часто спрашивают на собеседовании

### 1. В чём разница между EF Core и EF 6?

- **EF Core** — кроссплатформенный, легче, развивается (рекомендуется для новых проектов).
- **EF 6** — только .NET Framework, «классический» EF.

### 2. Что такое Lazy Loading и когда его не стоит использовать?

- **Lazy Loading** — навигационное свойство подгружается при первом обращении (нужен прокси или инжект ILazyLoader).
- Минусы: N+1 запросов, неочевидные обращения к БД. Часто лучше **Eager Loading** (Include) или **Explicit Loading**.

### 3. Что такое N+1 и как его избежать?

- Один запрос за списком сущностей + по запросу за каждой связанной коллекцией = N+1 запросов.
- **Решение:** загружать связи явно: `Include(x => x.Orders)` или проекции (Select с нужными полями).

### 4. AsNoTracking() — зачем?

- По умолчанию EF отслеживает сущности (Change Tracker) для обновлений при SaveChanges.
- **AsNoTracking()** — только чтение, быстрее и меньше памяти; сущности не привязаны к контексту.

### 5. Когда выполняется запрос к БД?

- При перечислении результата (foreach, ToList(), ToArray(), FirstOrDefault() и т.д.), а не при построении IQueryable. До перечисления — только строится дерево выражений.

### 6. IQueryable и IEnumerable в контексте EF

- **IQueryable** — запрос выполняется в БД (фильтры уходят в SQL).
- **IEnumerable** (например, после ToList()) — данные в памяти, дальнейшая фильтрация — в коде. Важно не вызывать ToList() раньше времени, чтобы не тянуть лишние данные.

### 7. Миграции: что это и зачем?

- **Миграции** — кодовая история изменений модели (таблицы, индексы, данные). Применяются к БД через `Database.Migrate()` или `dotnet ef database update`. Позволяют не править схему руками и держать её в репозитории.

### 8. Fluent API vs Data Annotations

- **Data Annotations** — атрибуты на свойствах/классах (`[Required]`, `[MaxLength]`, `[Table]`).
- **Fluent API** — в OnModelCreating: `modelBuilder.Entity<T>().Property(...).HasMaxLength(...)`. Больше возможностей, конфигурация вынесена из сущностей.

### 9. Как в EF выполнить «сырой» SQL?

- **FromSqlRaw** / **FromSqlInterpolated** — для запросов, возвращающих сущности.
- **ExecuteSqlRaw** / **ExecuteSqlInterpolated** — для INSERT/UPDATE/DELETE без маппинга. Осторожно с инъекциями: использовать параметры, не склеивать строки.

### 10. SaveChanges vs SaveChangesAsync

- **SaveChangesAsync** — асинхронный вариант, не блокирует поток; в веб-приложениях предпочтительнее для масштабируемости.

## Полезные команды (EF Core CLI)

```bash
# Установка глобального инструмента
dotnet tool install --global dotnet-ef

# Добавить миграцию
dotnet ef migrations add InitialCreate

# Обновить БД до последней миграции
dotnet ef database update

# Откатить последнюю миграцию
dotnet ef migrations remove
```
