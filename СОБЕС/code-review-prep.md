# Подготовка к Code Review на собеседовании .NET (Т-Банк)

По сценарию: **на примере простого кода попросят найти недостатки и предложить улучшения.**

---

## Что могут спрашивать (вопросы и формулировки)

1. **«Что не так в этом коде?»** — общий разбор фрагмента.
2. **«Какие риски / баги вы видите?»** — безопасность, многопоточность, граничные случаи.
3. **«Как бы вы это переписали?»** — рефакторинг, паттерны, читаемость.
4. **«Где могут быть проблемы с производительностью?»** — аллокации, блокировки, N+1, лишние запросы.
5. **«Как это протестировать?»** — тестируемость, зависимости, моки.
6. **«Соответствует ли это best practices .NET?»** — идиомы C#/.NET, стиль, соглашения.

---

## На что смотреть в первую очередь (чек-лист)

| Область | Что проверять |
|--------|----------------|
| **Ошибки и исключения** | Обработка `try/catch`, не глотаются ли исключения, корректный `throw` / перебрасывание |
| **Ресурсы** | `IDisposable`, `using`, не утекают ли соединения/потоки |
| **Асинхронность** | `async/await`, нет ли `.Result`/`.Wait()` в async-коде, `ConfigureAwait` где нужно |
| **Безопасность** | SQL-инъекции, логирование чувствительных данных, валидация ввода |
| **Null** | Проверки на `null`, nullable reference types, возможный `NullReferenceException` |
| **Читаемость** | Имена, длина методов, магические числа/строки, дублирование |
| **Зависимости** | Жёсткая связь с БД/HTTP, нарушение SRP, сложность тестирования |
| **Производительность** | Лишние аллокации, циклы в циклах, тяжёлые операции в циклах |

## Типичные фрагменты кода с недостатками (для тренировки)

### 1. Ресурсы и исключения

```csharp
public string ReadFile(string path)
{
    var stream = File.OpenRead(path);
    var reader = new StreamReader(stream);
    return reader.ReadToEnd();
}
```

**Проблемы:** нет `using` — утечка дескрипторов; нет проверки `path` на null/пустоту; исключения при открытии/чтении не обрабатываются явно.

**Улучшение:** `using` для `stream` и `reader`, валидация аргументов, при необходимости — обёртка в `try/catch` с логированием и перебросом.

---

### 2. SQL и безопасность

```csharp
public User GetUser(string userId)
{
    var query = "SELECT * FROM Users WHERE Id = '" + userId + "'";
    using (var cmd = new SqlCommand(query, _connection))
    {
        // ...
    }
}
```

**Проблемы:** SQL-инъекция (конкатенация строк), `SELECT *`, возможная утечка структуры БД.

**Улучшение:** параметризованные запросы (`SqlParameter`), явный список полей в SELECT.

---

### 3. Асинхронность

```csharp
public string GetData()
{
    return GetDataAsync().Result;
}
```

**Проблемы:** deadlock в контексте с `SynchronizationContext` (например, UI или ASP.NET до Core), блокировка потока.

**Улучшение:** везде async «до конца»: `async Task<string> GetData()` и `await GetDataAsync()`; не использовать `.Result`/`.Wait()` в async-цепочке.

---

### 4. Обработка исключений

```csharp
try
{
    DoSomething();
}
catch (Exception ex)
{
    // ignore
}
```

**Проблемы:** исключение полностью игнорируется, нет логирования, сложно отлаживать.

**Улучшение:** минимум — логировать; при необходимости — перебросить (`throw`) или обернуть в своё исключение; ловить более конкретный тип, если возможно.

---

### 5. Null и граничные случаи

```csharp
public int ProcessItems(List<Item> items)
{
    int sum = 0;
    foreach (var item in items)
        sum += item.Value;
    return sum;
}
```

**Проблемы:** `items` может быть `null` → `NullReferenceException`; нет проверки на пустой список (если это важно для логики).

**Улучшение:** проверка `items` (или контракт/атрибуты), при необходимости — `items?.Count ?? 0` или ранний выход.

---

### 6. Производительность и аллокации

```csharp
public string BuildMessage(List<string> parts)
{
    string result = "";
    foreach (var part in parts)
        result += part;
    return result;
}
```

**Проблемы:** конкатенация строк в цикле → много аллокаций и копирований.

**Улучшение:** `StringBuilder` или `string.Create` / `string.Join` в зависимости от задачи.

---

### 7. Тестируемость и зависимости

```csharp
public class OrderService
{
    public void CreateOrder(Order order)
    {
        var repository = new SqlOrderRepository();
        repository.Save(order);
        var emailService = new SmtpEmailService();
        emailService.SendConfirmation(order);
    }
}
```

**Проблемы:** жёсткое создание зависимостей внутри метода — нельзя подменить в тестах, нарушение DIP.

**Улучшение:** внедрение `IOrderRepository` и `IEmailService` через конструктор (DI).

---

### 8. Дублирование и «магические» значения

```csharp
if (status == 3) { ... }
// ...
if (user.Role == "ADMIN") { ... }
```

**Проблемы:** магические числа и строки, дублирование, сложнее менять и тестировать.

**Улучшение:** константы, enum, или типизированные объекты (например, роли как тип/значение).

---

## Кратко: что сказать на собеседовании

1. **Сначала** — явные баги и риски (безопасность, исключения, null, утечки ресурсов).
2. **Потом** — производительность и асинхронность.
3. **Затем** — дизайн: зависимости, тестируемость, читаемость и соглашения .NET.

Формулируйте конкретно: «здесь возможна SQL-инъекция», «здесь лучше использовать `using`», «здесь лучше async до конца, чтобы избежать deadlock».

---

## Полезные темы из .NET, которые часто всплывают в Code Review

- **IDisposable** и `using`
- **async/await**: не смешивать с `.Result`/`.Wait()`, `ConfigureAwait(false)` в библиотечном коде
- **Nullable reference types** и проверки на null
- **StringBuilder** vs конкатенация
- **Параметризованные запросы** к БД
- **Внедрение зависимостей** и интерфейсы для тестируемости
- **Логирование** (ILogger) вместо «глушения» исключений

Удачи на собеседовании.
