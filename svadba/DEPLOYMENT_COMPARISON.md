# Сравнение вариантов деплоя свадебного сайта

## Вариант 1: PHP в Docker

### Плюсы:
- ✅ Не нужно переписывать код
- ✅ Быстрый старт (если знаете PHP)

### Минусы:
- ❌ Нужно настраивать PHP-FPM + Nginx/Apache
- ❌ Два стека технологий (PHP + .NET в других проектах)
- ❌ Сложнее деплой в Azure (нужен PHP контейнер)
- ❌ Больше зависимостей и конфигурации

### Dockerfile для PHP:
```dockerfile
FROM php:8.2-fpm-alpine
RUN apk add --no-cache nginx
# ... много конфигурации
```

---

## Вариант 2: ASP.NET Core (РЕКОМЕНДУЕТСЯ) ✅

### Плюсы:
- ✅ **Уже есть готовый проект с Dockerfile**
- ✅ Простой деплой в Azure (родная поддержка .NET контейнеров)
- ✅ Один стек технологий (все в .NET)
- ✅ Лучшая производительность
- ✅ Проще поддерживать и развивать
- ✅ Razor Pages идеально подходит для статических страниц
- ✅ Легко добавить API для RSVP формы

### Минусы:
- ⚠️ Нужно переписать HTML в Razor синтаксис (но это просто!)

### Что нужно сделать:

#### 1. Скопировать статические файлы
```
Jack-Rose/public/assets/ → svadba/wwwroot/
  - css/ → wwwroot/css/
  - js/ → wwwroot/js/
  - img/ → wwwroot/img/
  - lib/ → wwwroot/lib/
```

#### 2. Конвертировать PHP в Razor
- `<?=HOME_ROOT ?>` → `~/` или `@Url.Content("~/")`
- PHP переменные → Razor `@Model` или `@ViewData`
- PHP includes → Razor `@await Html.PartialAsync()`

#### 3. Создать Razor Page
- `home.view.php` → `Pages/Wedding.cshtml`
- Использовать существующий `_Layout.cshtml` или создать новый

#### 4. Настроить статические файлы
- Уже настроено в `Program.cs` (`app.MapStaticAssets()`)

---

## План миграции в ASP.NET Core

### Шаг 1: Копирование ресурсов
```bash
# Скопировать все статические файлы
cp -r Jack-Rose/public/assets/* svadba/wwwroot/
```

### Шаг 2: Создание Razor Page
- Создать `Pages/Wedding.cshtml` на основе `home.view.php`
- Заменить PHP синтаксис на Razor

### Шаг 3: Настройка маршрутизации
- Настроить главную страницу как `/` или `/wedding`

### Шаг 4: Обработка RSVP формы
- Создать `Pages/RSVP.cshtml.cs` для обработки формы
- Можно использовать Email или сохранять в БД

### Шаг 5: Docker деплой
- Dockerfile уже готов!
- Просто `docker build` и `docker run`

---

## Время на миграцию

- **PHP в Docker**: 2-4 часа (настройка окружения)
- **ASP.NET Core**: 1-2 часа (копирование и конвертация)

---

## Рекомендация

**Использовать ASP.NET Core**, потому что:
1. У вас уже есть готовый проект
2. Dockerfile уже настроен
3. Проще деплой в Azure
4. Один стек технологий
5. Легче поддерживать

HTML/CSS/JS из PHP шаблона можно использовать практически без изменений!
